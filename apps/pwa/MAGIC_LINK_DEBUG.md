## ROOT CAUSE: Supabase Dashboard Configuration

**The issue is NOT in the code** - it's in the **Supabase project settings**.

Supabase has a **Site URL** setting that overrides the `emailRedirectTo` parameter when sending magic link emails. This is a security feature to prevent phishing attacks.

### Why This Happens

When you call:
```typescript
supabase.auth.signInWithOtp({
  email: 'user@example.com',
  options: {
    emailRedirectTo: 'https://6df264e2.kids-home-hub-pwa.pages.dev/auth/callback'
  }
})
```

Supabase does the following:
1. Receives the request with `emailRedirectTo`
2. Checks if `emailRedirectTo` is in the **Allowed Redirect URLs** list
3. If NOT in the list, it falls back to the **Site URL** setting
4. Uses the Site URL (probably `http://localhost:3000`) in the email

## Solution: Update Supabase Dashboard Settings

### Step 1: Go to Supabase Auth Settings
1. Visit: https://app.supabase.com/project/qojanjzukgkkrqmnyaai/auth/url-configuration
2. Log in to your Supabase account

### Step 2: Update Site URL
**Current value (likely):** `http://localhost:3000`
**Change to:** `https://6df264e2.kids-home-hub-pwa.pages.dev`

This is the default URL used for magic links.

### Step 3: Add Redirect URLs
Add the following to **Redirect URLs** (comma-separated or one per line):
```
http://localhost:3000/auth/callback
https://6df264e2.kids-home-hub-pwa.pages.dev/auth/callback
https://*.kids-home-hub-pwa.pages.dev/auth/callback
```

The wildcard `*` allows all preview deployments to work.

### Step 4: Save Changes
Click **Save** at the bottom of the page.

### Step 5: Test Again

2. Open browser console (F12)

## Additional Information

### Supabase Email Templates
Supabase uses email templates with variables. The confirmation URL is generated by Supabase based on:
1. The `emailRedirectTo` parameter (if whitelisted)
2. The Site URL (if `emailRedirectTo` is not whitelisted or missing)

Template variable: `{{ .ConfirmationURL }}`

You can check the email template at:
https://app.supabase.com/project/qojanjzukgkkrqmnyaai/auth/templates

### Why Localhost is Showing
Most likely, when you first set up the Supabase project, you were testing locally at `http://localhost:3000`, and that became the default Site URL. Now that you've deployed to production, you need to update it.

### Multiple Environments Strategy

**Option A: Single Supabase Project (Current)**
- Update Site URL to production
- Add all environments to Redirect URLs
- Code automatically detects correct URL

**Option B: Multiple Supabase Projects (Better for Production)**
- Create separate Supabase projects for dev/staging/prod
- Each has its own Site URL
- Use different environment variables per deployment
